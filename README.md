# Бесплатный принтер · Твой ФФ

Мини-приложение для загрузки PDF и печати на бесплатном принтере профкома. Работает самостоятельно и внутри iframe в [Твой ФФ](https://app.profcomff.com/apps/1).

## Разработка

Нужны Node.js 24 LTS и pnpm 12.18.0 (версия зафиксирована в `packageManager`).

```sh
npm install --global pnpm@12.18.0
pnpm install --frozen-lockfile
pnpm start
```

Приложение откроется на `http://localhost:9004`. `make run` запускает ту же команду.

Dev-сервер также принимает адреса проброшенных портов `*.coder.dyakov.space` для просмотра через Coder. WebSocket горячей перезагрузки использует адрес открытой страницы, чтобы браузер не обращался к `localhost` пользовательского устройства.

Ссылка на PWA-манифест использует `crossorigin="use-credentials"`, чтобы запрос включал cookies авторизации при просмотре через защищённый прокси Coder. Это не меняет авторизацию или CORS запросов к API.

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm exec playwright install --with-deps chromium
pnpm test:e2e
```

Браузерные тесты сами запускают dev-сервер, если он ещё не запущен. Запросы к печати и профилю подменяются: тесты не отправляют настоящих заданий на принтер. Проверяются загрузка, ошибки, история, мобильный QR с настоящим распознаванием тестового изображения через видеопоток и автоматическое заполнение профиля.

На каждый pull request workflow `.github/workflows/checks.yml` запускает два задания: ESLint и проверку TypeScript, unit- и браузерные тесты. Используются Node 24, версия pnpm из `packageManager`, кеш pnpm и установка по замороженному lockfile.

## Сборка и запуск

Сохранены Vue CLI, каталог `dist`, файлы `js/app.*.js`, `BUILD_MODE`, переменные `VUE_APP_*`, порт разработки 9004 и двухэтапная Docker-сборка с nginx на порту 80:

```sh
pnpm build --mode development
pnpm build --mode production
pnpm verify:build
docker build --build-arg BUILD_MODE=production -t print-ui .
docker run --rm -p 8080:80 print-ui
```

Builder обновлён до Node 24, runtime — до nginx stable. Пакеты устанавливаются через pnpm с замороженным lockfile. В обоих режимах сборки entrypoint имеет хеш в имени, как ожидает существующий nginx redirect; `pnpm verify:build` проверяет этот контракт на готовом `dist`. `default.conf`, `docker_entrypoint.sh`, сеть `web`, имена контейнеров, балансировка и параметры запуска контейнеров не менялись.

CI собирает и раскатывает тестовый образ при пуше в `main` или пуше тега `test/*` (например, `test/print-refresh`). Теги `v*` также запускают production-сборку и раскатку. Тестовый стенд: https://printer.ui.test.profcomff.com/.

Vue CLI остаётся на последнем опубликованном выпуске 5.0.9, поскольку менять схему сборки нельзя. TypeScript 6.0 — последний выпуск, поддерживаемый текущим TypeScript ESLint; Vue Router обновлён до 5.5. Удалено пустое Vuex-хранилище. CSS, иконки и шрифты не требуют внешних CDN. Модуль камеры загружается только при её включении; совместимый с QR-библиотекой WASM `zxing-wasm@1.1.3` собирается локально и исключён из предварительного PWA-кеширования.

## Настройки API

В `.env.development` и `.env.production` остаются прежние переменные:

- `VUE_APP_API_PRINTER` — базовый URL API печати, например `https://api.profcomff.com/print`;
- `VUE_APP_API_MARKETING` — URL аналитики;
- `VUE_APP_FEEDBACK_FORM` — ссылка на обратную связь.

Контракт печати: сначала `POST /file` получает PIN, затем `POST /file/{pin}` загружает PDF. Для быстрой печати `POST /qr` принимает токен с экрана терминала и от 1 до 10 уникальных PIN. Во время загрузки файла и ожидания QR-ответа внутренние переходы блокируются, а при закрытии вкладки браузер запрашивает подтверждение. Автоматических повторов запросов печати нет: после потери ответа нужно проверить экран принтера.

Клиент проверяет формат PDF, размер до 25 МБ, число копий 1–10 и синтаксис диапазонов страниц. Показанные ограничения размера/страниц сохранены из прежнего интерфейса; окончательные ограничения определяет сервер. В OpenAPI указан настраиваемый серверный предел размера по умолчанию 5 000 000 байт. Ошибки превышения размера/числа страниц обрабатываются отдельно.

[OpenAPI печати](https://api.profcomff.com/print/openapi.json).

## iframe и профиль Твой ФФ

Параметры `token`, `user_id`, `scopes` читаются из URL по примеру [rental-ui](https://github.com/profcomff/rental-ui/blob/main/src/store/profileStore.ts). Они сохраняются при внутренних переходах. Собственная шапка отсутствует, чтобы не дублировать шапку Твой ФФ. Область мини-приложения ограничена высотой iframe: содержимое прокручивается отдельно, а переключение печати и истории занимает постоянную нижнюю строку вне прокрутки. Если установленная оболочка обрезает iframe, высота и положение приложения подстраиваются под его видимую область через `IntersectionObserver`, без доступа к DOM родительского сайта. Это сохраняет доступ к меню в мобильных WebView; панель выбора файлов остаётся над ним, учитывается безопасная зона экрана.

Если передан токен, числовой `user_id` и хотя бы одно право `userdata.category.personal.read` / `userdata.category.credentials.read`, приложение автоматически запрашивает `GET /userdata/user/{id}` на том же API-хосте, что и сервис печати. Полученные поля `Личная информация / Полное имя` и `Учетные данные / Номер профсоюзного билета` заполняются по отдельности. Фамилия предлагается как первое слово ФИО и остаётся редактируемой. Уже начатый ввод не перезаписывается. При отсутствии данных или ошибке профиля остаётся ручной ввод. При доступной сессии профиля сохранённые реквизиты другого пользователя не подставляются.

Чтобы это заработало в Твой ФФ, соответствующие права должны быть делегированы мини-приложению в настройках сервиса. Административные права не нужны. Токен передаётся в заголовке `Authorization` только запросу userdata, не сохраняется в localStorage и исключён из URL аналитики. Он не заменяет проверку фамилии и билета в print API: полноценная печать по авторизованной сессии потребует изменения бэкенда.

[OpenAPI userdata](https://api.profcomff.com/userdata/openapi.json), [контейнер iframe Твой ФФ](https://github.com/profcomff/webapp-ui/blob/main/src/views/apps/ApplicationFrame.vue).

## QR и история

QR предназначен **только для телефона или планшета** и сканируется **только камерой**. На компьютере используется PIN на панели принтера. Камера включается по нажатию пользователя, предпочитает заднюю камеру и выключается при отправке задания/уходе со страницы. Во время скрытия вкладки сканирование приостанавливается. Повторные кадры не отправляют повторных заданий.

Родительский iframe должен разрешать `camera; clipboard-write`, сайт должен открываться по HTTPS. При запрете камеры пользователь видит инструкции и может распечатать по PIN.

Сохраняются последние 10 файлов в прежнем ключе `print-history`; старые записи поддерживаются. На мобильном устройстве можно выбрать несколько файлов и распечатать их одним сканированием. Если storage недоступен, загрузка продолжает работать, а экран результата предлагает сохранить PIN.
